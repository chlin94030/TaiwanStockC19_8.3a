# Alpha Radar V19.8.3a — 分階段穩定版（402母池備援／進度可視化）


## 19.8.3a 小修正

- FinMind `TaiwanStockInfo` 若回傳 402／權限限制，不再直接中止。程式會先改用既有快取；沒有快取時，改查證交所＋櫃買中心官方公開公司名冊，再開始 40 檔階段下載。
- 這個官方名冊仍是「目前公司名冊」，不是歷史成分股名冊，因此不改變原本研究限制。
- 任務畫面新增整體百分比、目前步驟、該步驟件數、已執行時間與最近更新時間。即使失敗，進度條仍停在失敗位置，不會只顯示 RUNNING／錯誤文字。
- 按 A／B 後會立即切到任務狀態畫面；背景任務每 2 秒刷新狀態。

V19.8.3a 延續 V19.8.3 的分階段設計，目的不是再把回測規模一次放大，而是把 Cloud 研究流程改成「小規模跑通 → 確認穩定 → 再升一階」。數值研究核心仍沿用 V19.8；本版主要修正工作量、記憶體、續跑與輸出方式，不因本次測試結果自動改動正式選股權重。

## Cloud 操作順序（重要）

Cloud 只開放以下四級：

1. S1：40 檔 × 4 個基準日，純價量。
2. S2：60 檔 × 6 個基準日，純價量。
3. S3：80 檔 × 8 個基準日，純價量。
4. S4：100 檔 × 12 個基準日，才開放營收／法人／融資；季報仍先不開。

150 檔以上不再讓 Cloud 網頁一鍵執行，改用 `run_v1983_staged.py` 離線逐段擴大。300／600 檔仍保留為研究目標，不是刪除功能。

每一階段請依序按：

- `A｜下載／補齊本階段資料`
- 成功後再按 `B｜用快取執行本階段驗證`
- 前一階段未完成時，下一階段會鎖住。

同一母池與種子使用前綴固定分層抽樣，因此 40 ⊂ 60 ⊂ 80 ⊂ 100，可沿用前一階段已抓好的股票快取，不會每次擴大就換掉整批股票。下載也改成小批次落盤，單批完成即保存；早期階段不產生大型完整因子面板與可攜式資料庫 ZIP。

## 離線逐步擴大

已有 diagnostic/replay ZIP 時：

```bash
python run_v1983_staged.py \
  --replay-bundle YOUR_REPLAY.zip \
  --steps 40x4,60x6,80x8,100x12,150x18,300x40,600x100 \
  --output data/v19/staged_v1983
```

每一階段使用獨立 Python 子程序；成功後寫入 stage JSON，下一階段失敗或超時時，前面結果仍保留，下次會直接續用，不必重跑。預設每一階段 900 秒上限，可用 `--stage-timeout` 修改。

工具會比較相鄰階段的最新研究因子支援集合與權重 L1 距離。預設「support Jaccard ≥ 0.75 且 L1 ≤ 0.20」才標示為穩定；即使穩定，也只代表權重沒有隨樣本規模明顯漂移，不代表已證明獲利，更不會自動把研究權重寫入正式交易設定。

## 本次真實歷史重播

使用既有 V19.8 真實歷史包（91 檔股票＋0050，63,843 根日線）實際做分階段測試：

- 40 檔／4 日期：12/12 案例完成，約 7.9 秒，峰值 RSS 約 329 MiB。
- 60 檔／6 日期：18/18，約 10.7 秒，約 437 MiB。
- 80 檔／8 日期：23/24，約 15.5 秒，約 551 MiB。
- 90 檔／12 日期：35/36，約 15.9 秒，約 611 MiB。

這份既有資料只有 91 檔股票，因此無法用它實測 100／150／300／600 檔；大型階段必須等實際資料逐步補齊後才可驗證。四個已測規模的最新研究權重相同，但 20／60 日平均相對 0050 超額仍為負，因此本版不據此調高或正式採用新權重。

## 重要界線

V19.8.3 已將使用者這次遇到的「一次放太大」路徑拆解並用既有真實資料驗證，但目前環境仍不能代替你的實際 Streamlit Community Cloud 工作階段、網路供應商配額或完整 600 檔資料。請先在 Cloud 只跑 S1；S1 完整成功後才升 S2。
